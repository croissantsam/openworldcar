OPENSTREETMAP — RÉFÉRENCE DES DONNÉES POUR UNE MAP 3D

Ce fichier liste les principaux objets, tags et valeurs OpenStreetMap (OSM), avec leur signification dans le monde réel et leur interprétation possible dans une map 3D.

IMPORTANT :
- OSM est une base de données ouverte et extensible.
- Tous les tags ne sont pas présents sur tous les objets.
- La couverture varie selon les pays, régions et contributeurs.
- Cette liste couvre les catégories et tags les plus utiles pour une map 3D / jeu de conduite, mais ne constitue pas la totalité des tags OSM existants.


======================================================================
1. STRUCTURE DE BASE OSM
======================================================================

node
→ Point géographique.

Exemples :
- feu de circulation
- arbre
- borne
- arrêt de bus
- sommet
- adresse
- POI

way
→ Ensemble ordonné de nodes.

Peut représenter :
- une ligne
- un contour
- un polygone

Exemples :
- route
- rivière
- bâtiment
- forêt
- lac
- parking

relation
→ Ensemble de nodes, ways et/ou autres relations avec une signification commune.

Exemples :
- restriction de virage
- ligne de bus
- ligne de train
- multipolygone
- frontière administrative
- itinéraire

tags
→ Paires clé/valeur décrivant l'objet.

Exemple :
highway=residential
lanes=2
maxspeed=50
oneway=yes

63. ATTENTION AUX DONNÉES MANQUANTES
======================================================================

Un objet peut être très simple :

building=yes

ou beaucoup plus détaillé :

building=apartments
height=24
building:levels=8
roof:shape=flat
name=Example

Il faut donc toujours prévoir des valeurs par défaut / fallback.

Exemple :

height disponible
→ utiliser height

sinon building:levels disponible
→ estimer la hauteur

sinon
→ utiliser une hauteur générique.

→ nodes + ways + relations


Pour une map 3D mondiale, les données OSM représentent principalement :
1. Où sont les choses.
2. Quelle forme elles ont.
3. Quel type de chose elles représentent.
4. Certaines propriétés physiques.
5. Certaines règles de circulation.
6. Certaines informations descriptives.

OSM ne fournit pas automatiquement un modèle 3D réaliste de chaque objet. La géométrie 3D, les textures, les détails, les arbres, les véhicules, les façades et une grande partie du relief doivent être générés ou provenir d'autres sources.
